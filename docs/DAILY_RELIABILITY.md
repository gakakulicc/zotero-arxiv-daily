# 信息充分、持续且可恢复的每日产出

目标是每天可靠地得到有依据的论文摘要。没有新增主观“论文质量分”，也没有因追求速度
减少候选数量、发送篇数或更换已经验证可运行的本地模型。相关性排序公式保持原样。

## 摘要改进

- 默认输入预算从 2000 提高至 4000 个 GGUF 模型 token，仍使用 Qwen2.5-3B Q4_K_M、
  8192 上下文及 512 输出 token。无需 LLM API。
- 为摘要、正文开头、方法、实验/结果、讨论/结论/局限分别分配空间。长引言不会先耗尽全部预算。
  支持常见 TeX、Markdown 和编号章节；无法识别时使用正文开头和结尾节选。
- 生成 2–3 句简要总结，包含核心贡献和节选明确报告的实验发现；材料未报告的结果、局限
  或机构不能猜测。信息更多不等同于已经证明摘要更准确，仍需人工抽查。
- 邮件注明“仅依据摘要”或“依据摘要与正文节选”；没有让模型假装读过整篇论文。

若 `CUSTOM_CONFIG` 显式设置 `llm.local.input_tokens: 2000`，它仍覆盖新默认值；
希望使用新预算时改为 4000，或删掉该覆盖项。其余旧 Secrets 可继续使用。

## 失败恢复与边界

- 摘要生成默认最多尝试两次。单篇失败继续处理其余论文，保留原始摘要并明确标注。
  降级结果不会作为成功摘要缓存，后续重跑可重新生成。
- 每完成一篇立即保存摘要与机构结果。重跑同一论文及相同模型/提示词配置时可直接恢复；
  改变输入预算、语言、模型等会重新生成。
- 缓存仅保存公开候选论文的生成结果及哈希标识，不保存 Zotero 文献库正文、邮箱或凭据，
  30 天后清理。GitHub 缓存仍可能被平台淘汰，缓存失效时重新计算。
- RSS 连接/读取以及 SMTP 有网络超时；TeX、HTML 和 PDF 解析在可终止的独立进程内执行。
  子进程使用 spawn，避免继承已运行的原生模型线程。
- 检索失败与“有效订阅源当天没有新论文”严格区分。完全检索失败会尝试发送故障通知，
  并使 Actions 失败以保留可见性；多个来源中某个失败时，邮件注明可能不完整。
- 每日任务与 Test 串行执行，不互相取消。上限 300 分钟；达到 240 分钟处理预算后，
  尚未生成的入选论文使用明确标注的原始摘要，给发信留出时间。不会减少入选篇数。

## 每日运行与发信

正式运行时间仍为北京时间 06:00；北京时间 08:17 再尝试一次。当天正式日报已获 SMTP
接受时，补跑跳过；只有失败通知不会抑制补跑。Test 的发信记录与正式日报分开。
手动 Run workflow 不受“当天已发送”跳过限制，可用于有意重新验证。

默认每天无新论文也发确认邮件。已有 `SEND_EMPTY=false` Variable 会继续跳过这种邮件；
如需每天确认，将其改为 `true`。

不在 SMTP 投递阶段盲目重试。连接在提交后断开时，程序可能无法确定服务器是否已接收，
再次发送存在重复风险。正常 QUIT 断连不再把已经接受的邮件错误报告为失败；部分收件人
被拒绝会明确报告。SMTP 接受不等于邮件已经到达收件箱，平台故障和服务商退信无法由本项目消除。
补跑去重依赖可用的 GitHub 缓存，是尽力恢复机制，不承诺严格一次投递。

## 如何检查结果

Actions Summary 会记录运行状态、入选数、生成成功数、摘要降级数及仅摘要证据数。
Artifacts 的 `daily-delivery-report`（Test 为 `test-delivery-report`）包含：

- `daily-email.html`：实际准备发送的内容，发信失败时仍尽力保留。
- `status.json`：`smtp_accepted`、`smtp_failed_or_unconfirmed`、`failure_notice_sent`、
  `already_delivered` 或 `empty_skipped` 等状态及计数。

报告仅包含公开候选论文与处理状态，不含私有文献库内容或凭据，保留 14 天。
CI 同时检查故障恢复用例和三篇不同输入结构的真实本地 Qwen 批量生成，真实模型异常时
不能靠原始摘要降级让该检查通过。完整私有 Zotero/SMTP 链路仍需 Run workflow 验证。
